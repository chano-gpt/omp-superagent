# omp-superagent 0.1.4

The Gateway and the per-session Host relay now run as Rust executables. The
Gateway connects only the configured Discord, Telegram and Slack adapters. An
idle lane no longer keeps a separate Bun process just to relay RPC. OMP itself
is still installed separately and has not been patched.

- The head reads new lane journal entries from its last observation and uses
  smaller notifications for intermediate streaming updates. Final messages,
  approvals and delivery receipts retain their original contents.
- Queue and board queries avoid loading unrelated messages just to check for
  work. `/restart` restores the original session and keeps intake on hold if
  its model or effective reasoning level cannot be reconciled.
- Discord voice work requests require written confirmation before reaching the
  head. Bound Discord work threads show activity and verified completion in
  their titles. Routine lane decisions stay internal; owner decisions appear
  on their original messenger cards.

## Install or upgrade

```sh
bun add --global --trust omp-superagent@0.1.4
omp-sa --help
```

Alternatively, use `npm install --global omp-superagent@0.1.4` with Bun on
`PATH`. Both installation paths require Git and Bun 1.4.4 or later. The npm
tarball includes both executables for macOS and Linux (x64 and arm64); it does
not require Cargo. A **source checkout or source tarball** also requires stable
Rust/Cargo, CMake and a C compiler. Installation does not start bots or replace
a running Gateway.

See the [operations guide](https://github.com/dbc-hbin/omp-superagent/blob/v0.1.4/docs/OPERATIONS.md)
for setup and shutdown. Compatibility tests use stock OMP and isolated messenger
fixtures; they do not establish live-account or paid-provider behavior.
